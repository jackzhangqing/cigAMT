cigAMT / USAGE GUIDE

Data, protocols, and availability.

cigAMT has two complementary sampling-rate branches and eight evaluation tasks. This guide distinguishes the benchmark specification from resources that are still being prepared for release.

Four synchronized components

The component order is Ex, Ey, Hx, Hy. Sampling rate denotes temporal sampling, not a claim that the useful signal bandwidth equals that rate. Amplitudes in normalized benchmark arrays should not be interpreted as calibrated SI units without the corresponding original calibration metadata.

Small preview package

A local candidate package contains eight sferic windows and one input/target view for each of the seven low-rate tasks. These samples explain the data interfaces; they do not reproduce full benchmark scores. The seven low-rate examples share one underlying reference window and are not seven independent field observations. The preview has not been uploaded to Hugging Face.

Preview arrays are stored in NPZ containers and can be loaded without pickle. The candidate package includes an array manifest, a dataset-card draft, checksums, and a loading example. No dataset license or permanent download location has yet been assigned.

from pathlib import Path
import numpy as np

# Run after obtaining and extracting a published preview package.
path = next(Path("samples").glob("*.npz"))
with np.load(path, allow_pickle=False) as sample:
    for name in sample.files:
        value = sample[name]
        print(name, value.shape, value.dtype)

Observation and loss masks

For missing-data tasks, observed_mask = True identifies available input entries; hidden entries are zeroed in the model input. The complementary loss mask identifies held-out positions. Future, internal-gap, and irregular-run targets are scored only at those positions. A zero input value by itself is not a reliable indicator of missingness.

Evaluation protocols

Window-level sferic identification

The 27 annotated records are split into 15 training, eight validation, and four test records. Windows from a source record stay in a single partition. Checkpoints are selected using validation AP; a validation-selected threshold is frozen for testing. The four test records are from Nanjing, so this evaluation does not establish cross-region generalization.

There are 11,260 / 3,130 / 2,488 original training / validation / test windows. One fixed augmented copy per training window produces 22,520 training entries. Validation and test windows remain unaugmented.

Controlled noise injection

Protocol A calibrates the noise independently for each electromagnetic component to achieve the target SNR. Protocol C allocates noise using electric/magnetic group energies; individual component SNRs can differ. The controlled whole-window settings are −30, −25, −20, −15, −10, and −5 dB.

The website’s compact noise-task and denoising tables follow the manuscript’s arithmetic summaries across A/C. Their reported dispersion values are descriptive; averaging summaries does not establish pooled uncertainty or statistical significance. Protocol-specific results and implementation settings belong to the complete benchmark release.

Task-specific scores

  • Sferic identification: AP, F1, precision, recall, MCC.
  • Noise classification: ten-noise-class Macro-F1 and accuracy, distinguished from all-11-class scores including clean and clean-input accuracy.
  • Noise localization: point F1, IoU, and event F1, with one-to-one event matching at temporal IoU ≥ 0.5.
  • Denoising: overall and bandwise NRMSE, SNR-related scores, Pearson correlation, and distortion on clean controls.
  • Forecasting, interpolation, imputation: MSE, MAE, NRMSE, and Pearson correlation computed only on held-out entries.

Frequency-component targets are low- and high-band time-domain waveforms from a 5 Hz FFT split. They sum to the reference waveform. No single score combines all eight tasks.

Impedance case studies

Impedance assessment complements sferic selection and both denoising tasks. Known-reference synthetic cases can quantify response errors. Unpaired field cases compare response curves and cannot establish clean-reference reconstruction accuracy. The field figure on the project page is such an unpaired case.

Code modules

The implementation is organized around four areas. The original research directories have been inspected read-only; they have not been modified or automatically published as part of the website.

  1. Sferic identification: four-component window loading, record-level partitions, sixteen classifier comparisons, and field-selection cases.
  2. Low-rate AMT benchmark: shared task interfaces, controlled injection, denoising, forecasting, interpolation, imputation, and specialist adapters.
  3. GeoAMT-DiT: four-component reference-signal generation with DDPM / DDIM sampling.
  4. Conditional Noise-DiT: structured-noise generation with noise-type and active-length conditioning.

Training, inference, and full benchmark reproduction have not been rerun for this website. Original implementation dependencies, checkpoints, and applicable third-party licenses must accompany a later code release.

Interpretation and scope

  • “Independent noise library” describes separate construction and supply, not a blanket claim of statistical independence.
  • Reference windows and derived task views may share source records or physical models.
  • Diffusion-generated benchmark extensions are reserved for training. This restriction alone does not verify the independence of every generator’s fitting sources.
  • Generated-reference quality diagnostics in the manuscript have pending reference/evaluator alignment and are not presented as a unified website ranking.
  • Event-level differences in the results refer to noise localization, not to window-level sferic classification.
